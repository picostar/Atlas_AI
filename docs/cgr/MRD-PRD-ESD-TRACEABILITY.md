# MRD PRD ESD Traceability

Use this file to map market evidence to market requirements, product requirements, engineering design inputs, and validation evidence.

This file is strongly recommended for CGR Bootstrap and Improve mode when enough source evidence exists.

## How To Use

1. Start from market evidence, source confidence, MRD problem statements, target segments, pain points, and success criteria.
2. Map each MRD item to PRD goals, use cases, requirement IDs, acceptance criteria, and verification methods.
3. Map each PRD requirement to ESD architecture, API, data model, monitoring, rollback, pilot, security, or operations sections.
4. Record validation evidence from tests, pilot, UAT, logs, analytics, dashboards, or operational checks.
5. Mark unresolved owner-required facts as gaps. Do not invent approvals, owners, pricing decisions, contracts, customer commitments, vendor support terms, or production readiness claims.

## Coverage Checks

- Every material market evidence item has an MRD need, pain point, or success criterion.
- Every MRD success criterion has at least one PRD goal or requirement ID.
- Every P0 PRD functional requirement has acceptance criteria and a verification method.
- Every P0 non-functional requirement has a target or limit and a verification method.
- Every PRD requirement that affects architecture, API, data, security, monitoring, rollback, pilot, or operations has an ESD section or design input.
- Every critical PRD acceptance criterion has validation evidence in tests, pilot, UAT, logs, analytics, dashboards, or operational checks.
